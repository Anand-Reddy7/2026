## 5. Understanding async and await in Python

In my RAG document ingestion pipeline, I process PDF and Markdown files, extract text, split it into chunks, and attach source metadata.
Initially, file processing was sequential, so each file had to finish before the next one started.
I introduced asyncio.gather() to coordinate multiple file-processing operations concurrently, and asyncio.to_thread() to offload blocking synchronous operations without blocking the event loop.
This improves responsiveness and can overlap I/O waits, although it doesn't guarantee faster PDF extraction because that work can be CPU-intensive.
For production, I'd benchmark the pipeline, use multiprocessing where appropriate for PDF extraction, and apply async primarily to network-bound embedding and vector database calls, with bounded concurrency.

## Python Decorater ?

Decorators use the @ syntax and commonly rely on closures and wrapper functions. ## LRU (Least Recently Used) ?
An LRU cache evicts the least recently used entry when capacity is exceeded. In Python, I can implement it using OrderedDict, where get() moves the accessed key to the end, and put() inserts or updates the key. If capacity is exceeded, I remove the first item using popitem(last=False). Both operations run in O(1) average time, with O(capacity) space complexity. If built-in ordered dictionaries are not allowed, I would implement it using a HashMap and a doubly linked list."


## File-level hashing vs chunk-level hashing
In my RAG ingestion pipeline, file-level hashing detects whether a document changed, but I use chunk-level hashing to minimize embedding regeneration. If one line changes in a 1,000-line document, I reparse the document, compare the new chunk hashes against previously indexed chunks, and generate embeddings only for chunks whose content changed. Unchanged chunks reuse their embeddings. I then reconcile the Qdrant points, update metadata, and remove obsolete vectors. To reduce unnecessary re-chunking, I prefer structure-aware chunking with stable section boundaries.

| Comparison | File-Level Hash | Chunk-Level Hash |
|---|---|---|
| One line changes | Entire file hash changes | Only affected chunk hashes change, if chunk boundaries remain stable |
| Embedding generation | Typically all chunks | Only new or modified chunks |
| Complexity | Simple | Moderate |
| Best use | Detecting changed files | Incremental RAG indexing |


## How do you build RAG pipeline effectivly?

I would design the RAG ingestion pipeline in Python with PyMuPDF for PDF parsing, native Python file handling for Markdown and TXT, RecursiveCharacterTextSplitter for chunking, OpenAI for embedding generation, and Qdrant as the vector database.
First, I recursively scan the document directory using Path.rglob(). For PDFs, I use PyMuPDF to extract text page by page, preserving the source filename and page number. For Markdown and TXT, I read the text using UTF-8 encoding.
Next, I split the extracted text using RecursiveCharacterTextSplitter with a chunk size of 400 and an overlap of 100 characters. Each chunk is stored with metadata such as source, page number, and chunk index.
Before processing a file, I generate a SHA-256 file hash and compare it against the previously indexed version in PostgreSQL. If the hash is unchanged, I skip ingestion.
If the document is new or modified, I generate chunk-level hashes. I compare the new chunks against previously indexed chunks to identify which embeddings can be reused and which need to be regenerated.
For new or changed chunks, I generate embeddings using OpenAI's text-embedding-3-small model, which produces 1536-dimensional vectors by default.
I store these embeddings in Qdrant with deterministic point IDs and metadata, using upsert operations. I also remove obsolete vectors when a document has changed.
For large-scale ingestion, such as 10,000 documents, I use batch processing, asynchronous workers, retries with exponential backoff, rate limiting, and a message queue. I track ingestion status in PostgreSQL and monitor failures, latency, and embedding costs.
This approach gives us a scalable, idempotent, and incremental RAG ingestion pipeline that avoids unnecessary embedding generation.

## Python asyncio vs Threading

Both asyncio and threading allow Python applications to handle multiple tasks concurrently, but they work differently.

The main difference:
- asyncio: Uses a single event loop thread by default and switches between tasks when they await.
- Threading: Uses multiple operating-system threads, and the OS scheduler manages execution.

## Flatten a deeply nested list
Write a recursive function to flatten a list containing arbitrarily nested lists.
Input: [1, [2, [3, 4], 5], [6, 7]]Output: [1, 2, 3, 4, 5, 6, 7]

```py
l = [1, [2, [3, 4], 5], [6, 7]]

new_list = []

def flatten(l):
    for i in l:
        if isinstance(i, list):
            flatten(i)
        else:
            new_list.append(i)
```

## Write a Parser to read the PDF and MD files

```py
from pathlib import Path
import pymupdf
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_core.documents import Document

# Read PDF 
splitter = RecursiveCharacterTextSplitter(
    chunk_size = 400,
    chunk_overlap = 100,
    separators = ["\n\n", "\n", " ", ""]
)

def read_pdf_files(path):
    documents = []

    for file_path in path.rglob("*.pdf"):
        print("Processing PDF is:", file_path.name)
        try:
            with pymupdf.open(file_path) as doc:
                print("Total pages:", len(doc))

                for page_number, page in enumerate(doc, start=1):
                    text = page.get_text("text")

                    if not text.strip():
                        continue

                    chunks = splitter.split_text(text)

                    for index, chunk in enumerate(chunks, start=1):
                        document = Document(
                                    page_content = chunk,
                                    metadata = {
                                        "source": str(file_path),
                                        "file_name": file_path.name,
                                        "page_number": page_number,
                                        "chunk_index": index
                                    }
                                )
                        documents.append(document)
            print("Total PDF Chunks:", len(documents))
        except Exception as error:
            print(f"Exception while processing {file_path.name} as {error}")
    return documents

def read_md_files(path):
    documents = []

    for file_path in path.rglob("*.md"):
        print("Processing MarkDown file is:", file_path.name)
        try:
            text = file_path.read_text(encoding="utf-8")
            if not text.strip():
                continue

            chunks = splitter.split_text(text)

            for index, chunk in enumerate(chunks, start=1):
                document = Document(
                    page_content = chunk,
                    metadata = {
                        "source": str(file_path),
                        "file_name": file_path.name,
                        "chunk_index": index
                        }
                    )
                documents.append(document)

            print("Total MD Chunks:", len(documents))

        except Exception as error:
            print(f"Exception while processing {file_path.name} as {error}")

    return documents

if __name__ == "__main__":
    path = Path("./knowledge")
    pdf_reader = read_pdf_files(path)
    md_reader = read_md_files(path)
    all_documents = pdf_reader + md_reader
    print("All PDF Chunks :", len(pdf_reader))
    print("All MD Chunks :", len(md_reader))
```

[
    {'tool': 'get_pod', 'args': {'pod': 'payments-1'}, 'request_id': 'r1'},

unique_events = set()
answer = []
for event in events:
    key = (event["tool"], event["args"]["pod"])
    if key not in unique_events:
        unique_events.add(key)
        answer.append(event)
