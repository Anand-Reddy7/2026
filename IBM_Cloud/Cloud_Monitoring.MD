# IBM Cloud Monitoring

---

## What is IBM Cloud Monitoring?

IBM Cloud Monitoring is a **managed observability and monitoring service** used to monitor infrastructure, applications, and platform services on IBM Cloud.

### What It Monitors

| Resource | Examples |
|---|---|
| **Virtual Servers (VSI)** | CPU, memory, disk, network |
| **Kubernetes / OpenShift** | Cluster health, pod metrics, node status |
| **Bare Metal Servers** | Hardware-level metrics |
| **Applications & Containers** | App performance, container resource usage |
| **IBM Cloud Platform Services** | VPC, Load Balancer, VPN, Object Storage |

### What It Helps You Do

- Monitor CPU, memory, disk, and network usage
- Create **alerts** for threshold breaches
- Build **dashboards** for real-time visibility
- Troubleshoot performance issues
- Observe Kubernetes workloads

## Two Types of Metrics

| Type | Source | Agent Required |
|---|---|---|
| **Platform Metrics** | IBM Cloud Services | ❌ No |
| **Infrastructure Metrics** | Your VM / Kubernetes node | ✅ Yes |

---

## Platform Metrics

Platform Metrics are metrics **automatically generated by IBM Cloud services** and sent to your IBM Cloud Monitoring instance.

- You do **not** need to install any monitoring agent
- IBM Cloud itself collects and publishes them automatically

### Common Platform Metrics

| Service | Metrics Available |
|---|---|
| **VPC** | Incoming/outgoing traffic, packet rate |
| **Load Balancer** | Active connections, request count, throughput |
| **Kubernetes** | Worker node status, cluster health, pod metrics |
| **VPN Gateway** | Tunnel status, bandwidth |
| **Object Storage** | Request count, storage utilization |

### Platform Metrics — Real Example

Suppose you created a VSI:

| Without Platform Metrics | With Platform Metrics |
|---|---|
| OS-level CPU | VPC network traffic |
| Memory | Instance lifecycle events |
| Disk | Hypervisor / network layer metrics |
| *(via monitoring agent only)* | Cloud-level telemetry |

## Agent Configuration

To collect **infrastructure metrics** from a VSI, install and configure the Sysdig monitoring agent.

### Step 1 — Install the Agent

```bash
curl -sL https://ibm.biz/install-sysdig-agent | sudo bash -s -- \
  --access_key ==ACCESSKEY== \
  --collector ==COLLECTOR== \
  --collector_port 6443 \
  --secure true \
  --check_certificate false \
  --additional_conf 'sysdig_capture_enabled: false\nremotefs: true\nfeature:\n mode: monitor_light'
```

### Step 2 — Stop and Disable the Agent Temporarily

```bash
systemctl stop dragent
systemctl disable dragent
```

### Step 3 — Inject Configuration Values

```bash
SYSDIG_CONFIG_FILE="/opt/draios/etc/dragent.yaml"

sed -i "s/==ACCESSKEY==/$cloud_monitoring_access_key/g" $SYSDIG_CONFIG_FILE
sed -i "s/==COLLECTOR==/$cloud_monitoring_ingestion_url/g" $SYSDIG_CONFIG_FILE
```

### Step 4 — Add Custom Tags

```bash
echo "tags: type:compute,lsf:true" >> $SYSDIG_CONFIG_FILE
```

### Step 5 — Enable and Restart the Agent

```bash
systemctl enable dragent
systemctl restart dragent
```

## Configuration Variables Reference

| Variable | Description |
|---|---|
| `$cloud_monitoring_access_key` | Access key for your IBM Cloud Monitoring instance |
| `$cloud_monitoring_ingestion_url` | Ingestion endpoint URL for your region |
| `tags: type:compute,lsf:true` | Custom tags to identify LSF nodes in dashboards |
